# Closed conserved withdrawal stage

This is an authorized private kernel extension. It adds injected sign-only and RPC adapters and offline fixtures, with no runtime import, public route, generated key, actual network transaction or activation flag. The old `live_*` prototype is neither read nor credited. The immutable LIVE namespace and game conversion remain unchanged.

## Design and interfaces

Use the existing `ac_operations`, account resource locks, immutable batches/postings and receipt journal. A withdrawal owns an immutable `withdrawal-v1` request and the same account lock used by world/events. `reserveWithdrawal({accountId,id,atoms,destinationTokenAccount})` binds the server-resolved wallet, fixed mint/network/treasury, exact positive u64 atoms and destination. It moves available vault claims into `withdrawal_reserved` atomically; no world/pool/escrow claim becomes available by implication.

`prepareWithdrawal(accountId,id)` verifies the configured conventional mint, destination owner and total treasury coverage. It resolves the latest finalized blockhash's actual origin with finalized `getBlock(contextSlot)`: the returned blockhash must exactly match and its blockHeight must be finite. The unsigned plan, origin slot/height and last-valid height become durable **before the signer is invoked**, without assuming a fixed validity-window length. Preparation resumes that same immutable plan after a crash. It builds one exact legacy TransferChecked plus domain-bound memo, obtains an injected transaction-only signature, and verifies the complete message/signature. Signed bytes and signature become durable before any send. Concurrent preparation chooses one persisted plan/result; discarded signatures are never submitted. An unsigned prepared hold is not automatically cancelled by time or a signing timeout.

`broadcastWithdrawal(accountId,id)` checks coverage again, persists pending before calling the injected RPC, and submits only those exact persisted bytes. Errors, preflight failures, unexpected replies, process exit and timeouts never release claims. Retrying never changes blockhash or signs a replacement. `reconcileWithdrawal(accountId,id)` accepts only a finalized matching raw signed transaction and consistent outcome. Success removes reserved claims and recorded external reserve in one batch; failure restores the vault once. Expiry additionally requires the explicit archival completeness witness below; ordinary RPC height/invalidity/history-floor/null checks on two sources are corroboration only. Missing/inconsistent evidence remains held.

## Required archival completeness witness

The configured archival adapter must expose a reviewed `completenessPolicyId` and `proveCompleteAbsence(request)`. This is a trusted server proof-provider contract, never a client assertion or an ordinary RPC method. The request binds provider/policy, LIVE namespace/config/genesis, signature, blockhash, its persisted origin slot/height, last-valid height and the observed finalized post-expiry slot/height. The result kind is `complete-finalized-block-window-v1` and must echo those bindings, `absent:true`, and an auditable lowercase SHA256 `evidenceHash`. It attests a contiguous complete finalized-block scan with `firstScannedHeight <= blockhashOriginHeight`, `lastScannedHeight >= lastValidBlockHeight`, and a finalized boundary at least as new as the independently observed post-expiry boundary. Its finite `finalizedHeight` must exceed last-valid height; the persisted origin cannot be substituted. The checked witness and corroborating RPC observations are journaled immutably before release.

No production scan/provider implementation or policy approval is supplied by this stage. Fixture witnesses are exclusively offline test data. A missing capability, incomplete transaction index, foreign witness or missing coverage keeps the hold. Distinct source ID strings do not establish completeness or independence.

The official [getFirstAvailableBlock documentation](https://solana.com/docs/rpc/http/getfirstavailableblock) describes a ledger's lowest retained block, not complete transaction indexing. [getTransaction](https://solana.com/docs/rpc/http/gettransaction) returning null does not attest transaction absence across the complete validity window. [getBlock](https://solana.com/docs/rpc/http/getblock) exposes the blockhash and nullable blockHeight used for strict origin verification; a missing/mismatched origin fails closed. No standard-RPC completeness inference replaces the reviewed witness capability.

`withdrawal(accountId,id)` is owner scoped. `pendingWithdrawals({afterId:null,limit:50})` is a private capped listing in stable ID order with a next cursor; workers must repeat complete sweeps so newly inserted earlier IDs are not skipped forever. Recovery reads require no signer and replay uses the bound wallet/destination even if the account's current wallet changes.

All claims, including world, pools, escrows and holds, count toward solvency. Finalized treasury/mint observations must cover the current complete journal and reach the highest known deposit, signed-blockhash, withdrawal-result and reserve-observation slot. Recheck inside the SQLite transaction after asynchronous proof/sign calls; a concurrent deposit or outgoing settlement can invalidate an earlier observation. A chain debit observed before local settlement can conservatively freeze other signing/broadcast until its known receipt is reconciled; it never causes a refund or subtraction of an unproven pending payment.

## Schema and worker fence

Append `ac_schema(3,'conserved-withdrawals-v1')` on first reservation, only after every pre-extension operation and resource lock has drained. Keep the existing version-2 marker and every posting/configuration unchanged. Existing tests/unused kernels continue to use schema 2. Old software refuses the additional marker when opening the file. **Stop every old worker/kernel process before extension activation, then drain with its original reviewed implementation.** A marker checked at open cannot stop an already-open old connection. Do not mix worker versions. Preserve arbitrary pending world/event locks; no migration clears them.

## Remaining trust and launch gates

The signer must only return transaction bytes and must never broadcast or independently send discarded signatures. Independently reviewed provider policy, actual complete-block coverage/evidence retention and the production witness implementation remain open gates; fixture policy IDs and hashes establish no real-chain capability. SOL fees/custody, actual core money/save/login/event integration, production workers, backup/restore, monitoring, final mint/conversion acceptance and explicit launch approval remain separate gates. A CA enables nothing by itself.
